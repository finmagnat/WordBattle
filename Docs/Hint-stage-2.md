# Подсказка: этап 2

Источник механики: [WordBattle — База знаний, вкладка «Бустер Подсказка»](https://docs.google.com/document/d/1cBsEHBgVm1XL-DUOUmvhqAMThI8pSTXbMuSs_DEKqtA/edit?tab=t.wm3fp5coem9). Вкладка прочитана полностью. Магазин, награды, рекламные пакеты и источники получения Буковки в этот этап не входят.

## Состояние и сохранение

`GameBoosterController` владеет одним `HintState`. Данные: `active`, `targetWord`, `orderedPath`, `letter`, `cellIndex`, `targetLength`, `passPending`, `timedOut`. Копирование состояния для снимков глубокое по массиву пути.

`SaveGameData.hint` — необязательное поле для manual save и Auto Recovery. Остаток времени хранится существующими `maxSeconds/currentSeconds`. Версия игровой механики не изменяется. `SaveGameStorage` нормализует пустой неактивный объект, который может создавать `JsonUtility`, в отсутствие Hint. Старые файлы без поля загружаются как обычные раунды.

Проверяется соответствие буквы и позиции полю, длины слову, отсутствие повторений клеток, ортогональная смежность и порядок букв пути. Повреждённый активный Hint не становится валидным recovery-снимком.

Ручное сохранение активного Hint сохраняет поставленную букву вместо обычной отмены provisional move. При сворачивании приложения сохраняется текущий checkpoint. Загрузка восстанавливает подсветку и статус длины без поиска и без операций inventory.

## Поиск

Hint перебирает все длины от максимально возможной на поле до двух, независимо от сложности AI/Letter. Результат поиска теперь содержит позицию и символ вставки и ordered path. Путь экспортируется в порядке чтения слова, а не в порядке DFS от вставленной буквы. Поиск также перебирает альтернативные варианты префикса, если первый мешает построить суффикс; отмена проверяется после yield и перед изменением поля.

Letter использует тот же поиск с прежними настройками и сохраняет прежний сценарий автоприменения. Общие исправления касаются корректности результата поиска, а не правил или сценария Буковки.

## Исходы попытки

| Событие | Результат |
| --- | --- |
| Исходное максимальное слово | Обычные очки и история, без reveal |
| Другое валидное слово максимальной длины | Такой же успех; сравнивается длина, а не текст |
| Более короткое валидное слово | Обычные очки и история; затем информационный reveal максимума |
| Невалидное слово/ошибка выбора | Обычная проверка и существующий popup; выбор очищается, Hint-буква и target/path сохраняются |
| Cancel | Буква и Hint удаляются, reveal и refund отсутствуют; можно поставить букву вручную |
| Skip/timeout | Reveal до удаления provisional letter и одного обычного пропуска |
| Поиск без результата | Нет новой буквы/состояния, один возврат Hint существующим API |
| Повторный Hint/Letter при активном Hint | Отклоняются до списания; клавиатура не создаёт вторую букву |
| Eraser/Swap/Mixer | Сохраняют прежнюю отмену текущего provisional move перед своим действием |
| Slowdown | Действует совместно с Hint, завершается перед reveal |

## Reveal и защита от повторных переходов

Переиспользованы `WordsField`, подсветка клеток, DOTween и статус игрового экрана. Прозрачный полноэкранный UI-слой блокирует остальные действия и завершает показ по тапу, включая повторные тапы. Отдельного popup нет.

Клетки показываются по ordered path с шагом 80 мс и небольшим scale punch. После пути остаётся пауза 1,5–2 секунды. Обычный показ занимает около 2,5–3 секунд; для предельного слова в 25 клеток — около 3,5 секунд, поскольку сохраняются и темп пути, и пауза чтения. Таймер во время reveal остановлен. Буквы поля, очки и история самим reveal не изменяются.

После короткого слова сначала полностью завершается обычный commit и сохраняется canonical state следующего хода, затем показывается reveal. AI запускается только после показа. При восстановлении этого checkpoint повторного принятия слова, начисления очков или reveal нет: выполняется следующий ход AI.

Во время reveal Skip/timeout pass ещё не засчитан. Снимок хранит `passPending`; при восстановлении такой pass выполняется один раз без повторения анимации. Только для корректного pending timeout допускается `currentSeconds == maxSeconds`.

Параллельные GameGo/Skip/Cancel/timeout блокируются состояниями сохранения/разрешения Hint. Смена поколения хода/операции и отмена reveal при скрытии экрана/новом раунде не дают старым продолжениям изменить новый раунд. Все reveal-tweens убиваются, scale и временная подсветка очищаются.

## Быстрая ручная проверка в Editor

1. Запустить `Main.unity`, войти в раунд. Через SRDebugger → Dev/Inventory выдать себе Подсказки; для наблюдения можно увеличить время хода.
2. Нажать Hint: во время поиска таймер стоит, после него выделена одна буква, статус показывает длину, направление скрыто.
3. Попробовать второй Hint/Letter и клавиатуру: второй буквы и второго списания быть не должно.
4. Составить максимальное слово, затем в новом ходе альтернативное той же длины: обычный зачёт без reveal.
5. Составить более короткое валидное слово: проверить свои очки, последовательное раскрытие максимума, читаемость статуса и переход AI. Повторить с быстрым двойным тапом во время показа.
6. Отправить невалидное слово: закрыть обычное сообщение, убедиться, что Hint-буква, длина и таймер сохраняются.
7. Нажать Cancel: буква исчезает без возврата бустера, ручной ход снова доступен.
8. Отдельно проверить Skip и истечение времени: раскрытие, удаление буквы, ровно один пропуск и ход AI.
9. Сохранить и выйти с активным Hint, загрузить раунд. Также свернуть приложение/восстановить recovery: буква, длина и время сохранены, нового списания/поиска нет.
10. Проверить читаемость длинного слова на узком Android-экране и во всех трёх скинах/локалях, а также Hint после Ластика и совместно с Замедлялкой.

Этапы 3–4 не начаты. Формат получения Hint и экономика не изменялись. Перед следующим этапом остаётся игровая оценка темпа reveal и текстов на реальном устройстве.
