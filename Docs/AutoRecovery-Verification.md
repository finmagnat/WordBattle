# Auto Recovery: доработка и проверка

## Результат 16.10.2026

Unity `6000.3.22f1`: финальный прогон autosave-3 **99/99 проверок PASSED** — 85 в первой Play Mode сессии и 14 после настоящего Stop/Play. Включены все прежние 48 проверок и 51 новая. Неожиданных ошибок Console во время тестов и teardown нет. Файлы production recovery и ручных сохранений не изменились; реальные операции PlayFab не выполнялись. Подробный протокол: [AutoRecovery-PlayMode-Results.md](AutoRecovery-PlayMode-Results.md).

Компиляция успешна. В финальной Console остаются два предупреждения внешних компонентов: SRDebugger создаёт EventSystem в пустой тестовой сцене; Unity Localization сообщает об атрибуте Serializable у `AssetTypeMetadata`. Они не относятся к изменённой логике сохранения и не исправлялись.

## Изменения

- `IGameBoosterHost.CancelCurrentMove` / `GameController`: возвращает признак отмены установленной временной буквы. Сброс только визуального выделения не считается изменением `SaveGameData`.
- `GameBoosterController.ActivateBoosterMixerAsync`: при неудачном перемешивании сохраняет checkpoint, только если перед поиском была отменена временная буква. Запись выполняется после завершения изменений поля и до асинхронного возврата бустера.
- `GameBoosterController.ActivateBoosterLetterAsync`: аналогичная запись после неудачного поиска слова, до возврата Буковки. Отсутствие кандидатов проверяется настоящим `SmartWordAlgorithmAsync`.
- `GameBoosterController.RollbackEraserAsync`: возвращает признак выполненного отката. `GameController.OnGameGo` не записывает второй checkpoint, если откат уже сохранил состояние перед возвратом Ластика.
- `GameBoosterController.EndSlowdown`: завершение логического эффекта определяется наличием активного host. Визуальный счётчик может завершиться раньше обработчика; это больше не мешает очистить эффект в checkpoint и возобновить таймер.
- `InventorySyncService.TryUseBoosterAsync` / `GrantBoosterAsync`: методы сделаны виртуальными для изолированной серверной заглушки. Их рабочая реализация и протокол PlayFab не изменены.

Формат сохранения в этой задаче не менялся. Из предыдущей задачи сохраняется необязательное поле `eraserRemovalCommitted`.

## Аудит остальных веток

Отмена выбора Менялки/Ластика и откат удаления уже сохраняют завершённое локальное состояние **до** запроса возврата. Отказ возврата не оставляет данных для повторной компенсации при recovery. Отказ списания происходит до отмены хода, поэтому сам по себе не требует нового checkpoint. Успешные полевые бустеры сначала фиксируют Ластик и затем записывают checkpoint.

`SaveRecoveryCheckpoint` по-прежнему запрещает запись во время сохранения принятого слова и штатного выхода. Завершение раунда выключает игру до удаления recovery. Изменения не добавляют запись внутри анимации принятого слова.

## Финальный аудит отмен (autosave-3)

Подтверждены пропуски checkpoint после повторного слова и окончания мигания. Также подтверждён аналогичный путь через `GetGameData(cancelPendingMove: true)`: этот getter используется не только при штатном сохранении/выходе, но и при чтении данных для окна выхода, после которого игрок может продолжить раунд.

`GameController.Cancel()` теперь возвращает прежний признак фактической отмены временной буквы; `IGameBoosterHost.CancelCurrentMove()` делегирует ему. Общий `CancelAndSaveRecovery()` вызывает существующий `SaveRecoveryCheckpoint` только при `true`. Внутри базового `Cancel` безусловной записи нет: транзакционные вызовы по-прежнему завершают откат, перемешивание или переключение очереди до сохранения.

Для окон ошибок фиксируются поколения очереди и текущей временной буквы. После закрытия настоящего AdvicePopup обработка продолжится только для исходного хода. `ModeBlinkEndEvent` передаёт клетку и поколение буквы, сохранённое при запуске мигания; контроллер дополнительно проверяет ожидаемую клетку и очередь. Старые Advice/Blink callback не отменяют новый ход, не разблокируют его UI и не записывают checkpoint. Эти значения служебные и не добавляются в `SaveGameData`.

При отмене или исключении поиска Буковки сохраняется только известное завершённое состояние: если временная буква была отменена, операция всё ещё актуальна, AI не зарегистрировал новую букву и поле совпадает со снимком после отмены. Если исключение возникло посреди применения AI, новый checkpoint не создаётся: остаётся предыдущий валидный snapshot. Это не новый механизм отката и не изменение правил возврата бустеров.

| `OnErrorPlayer(WordAlreadyBeen)` | Да, если буква ещё есть | `CancelAndSaveRecovery` после завершения popup и проверки исходных поколений |
| `OnErrorPlayer(SetLetterNoSelected)` | Нет: начинает только мигание | Checkpoint не нужен; источник мигания и поколение запоминаются только после актуального popup |
| `OnModeBlinkEnd` | Да, при действующей временной букве | Проверка клетки, поколения буквы, очереди, активности, выхода и `_isSavingWord`, затем общий helper |
| `OnErrorPlayer(NoLetterInstalled / WordNoSelected)` | Нет | Только окно совета; нет записи |

| `GetGameData` во время принятия слова | Отмена запрещена | Getter не меняет поле и не пишет промежуточный checkpoint |
| `OnGameGo`: отсутствующее слово | Да: отмена буквы, затем возможный откат Ластика | После завершённого отката — его checkpoint; иначе одна запись отмены. Перед отложенным откатом и после ожиданий проверяются исходные поколения |
| `PassedGame` из `OnTimeExpired / TryConfirmPass` | Да: отмена буквы, счётчик пропусков, очередь | Не сохраняет между отменой и пропуском. | `CheckFinishGame`: auto-mix после двух пропусков | Может менять поле; `Cancel` также очищает выбор | Поле перемешивается синхронно; запись следующей очереди выполняется после результата перемешивания |
| `IGameBoosterHost.CancelCurrentMove` | Да, при наличии буквы | Делегирует одному `Cancel`; полевой бустер выбирает запись после своего конечного результата |
| `ActivateBoosterMixerAsync` | Отмена буквы и/или перемешивание | Успех: фиксация Ластика и checkpoint; неудача: checkpoint только при фактической отмене, до refund |
| `ActivateBoosterLetterAsync` | Отмена буквы и/или установка подсказки | Успех и неудача сохраняются по прежним правилам; отмена/исключение до изменения AI сохраняет завершённую отмену только для актуальной операции и неизменившегося поля. Частичное применение не сохраняется |
| `ActivateBoosterEraserAsync / ActivateBoosterSwapAsync` | Отмена буквы и сохраняемый pending-режим | Checkpoint после открытия выбора; поколение операции исключает запись из старой анимации |
| Завершение Eraser / Swap в `OnCellSelectSuccess` | Да, поле и состояния бустеров | Синхронное применение и фиксация, затем checkpoint. Открытие выбора само по себе не фиксирует Ластик |
| `OnHoleOverlayCloseButtonClicked` | Да, снимает pending-режим Eraser/Swap | Checkpoint после снятия режима, до запроса возврата |
| `CancelEraserMode / CancelSwapMode` при тайм-ауте | Да, снимают pending-режим | Входят в транзакцию пропуска: следующий checkpoint после изменения очереди либо удаление recovery при финале |
| `RollbackEraserAsync` | Да, восстанавливает букву и снимает данные возврата | Checkpoint после полного отката и до async refund; повторное выполнение не возвращает бустер снова |
| `CommitEraserRemoval` | Да, снимает обратимость и старые данные отката | Входит в успешную транзакцию полевого бустера до его checkpoint |
| `StopSlowdown / EndSlowdown / CancelSlowdownTracking` | Логический конец эффекта — да; отмена token сама по себе — нет | Активный эффект снимается, затем host checkpoint. При принятии слова запись откладывается до завершения хода; при финале/выходе запрещена |
| `ResetForOpponentTurn` | Да, снимает данные Ластика | Вызывается до checkpoint следующей очереди; инвалидирует старые async операции бустеров |
| `ResetForNewGame / OnGameFinished` | Да, сбрасывают эффекты и откат | Начало: initial checkpoint после полного заполнения состояния. Финал/выход: только удаление, без нового checkpoint |
| `WordsFieldManager.Cancel / WordsFieldData.Cancel` | Удаляет `_setItem`, очищает выбор | Единственная игровая цепочка вызывается через `GameController.Cancel`; независимого пути обхода checkpoint нет |
| `WordsFieldData.Clear` | Может снять ссылку на временную букву, само поле не меняет | После принятия слова / успешного Mixer входит в соответствующую завершённую транзакцию |
| `WordsFieldData.Reset / SetSaveGameData` | Да, создаёт исходное/восстановленное поле | Выполняется синхронно при запуске до initial checkpoint; старые callback контроллера уже инвалидированы |
| `CellSelectCancel`, перенос пустой клетки, `BacktrackOneStep` | Нет: меняются только выбранная клетка и путь слова | Выбор и путь не входят в `SaveGameData`; лишней записи нет |
| `SelectableLetter.ModeBlinkClear / Highlight / UnHighlight / ShowLetter` | Нет: визуальное состояние | Checkpoint не нужен. Реальный `Update` сообщает о завершении мигания отдельно, с идентичностью исходной буквы |
| `GameScreenBase.CancelLetterThinking`, `AIGameController.AbortSearch`, `SmartWordAlgorithmAsync.Cancel` | Сам token/флаг — нет; предшествующий поиск мог отменить букву | Проверены завершённая отмена поиска и переходы жизненного цикла; исходный контроллер бустеров проверяет поколение операции |
| `GameController.Dispose` | Только прекращает работу контроллера | Инвалидирует поколение и активность; поздние окна не сохраняют и не изменяют уже выгруженную игру |
| Отказ/задержка списания, завершение возврата | Инвентарь не входит в `SaveGameData` | Старый ответ не начинает `CancelCurrentMove` в новом раунде. Refund вызывается после локального checkpoint и не требует новой записи |

Отмены сетевого мониторинга, переключения скина и таймеров внутри popup не меняют игровое поле, эффекты раунда или данные отката. Они исключены из механизма checkpoint; серверные правила компенсации не менялись.

Изменённые классы этого этапа: `GameController`, `GameBoosterController`, `WordsFieldManager`, `WordsFieldData`, `SelectableLetter`, `ModeBlinkEndEvent`; дополнен постоянный `AutoRecoveryPlayModeSuite`. Модель сохранения и хранилище не изменялись.

## Изолированные Play Mode тесты

Запуск: **Tools → Tests → Run isolated Auto Recovery Play Mode suite**.

Координатор выбирает пустую сцену `Assets/Scenes/Tests/AutoRecoveryTests.unity` **до входа в Play Mode**. Обычный `Main` / `CoreInstaller` не запускается. Тесты отказываются работать в другой сцене или вне собственного каталога `.utmp/AutoRecoveryTests/<run-id>/`.

Работают настоящие `GameController`, `GameBoosterController`, `WordsFieldManager`, события ввода, алгоритмы AI/Миксера, игровые UI prefab, анимация принятого слова, `RoundAutoSaveService`, валидатор и атомарное файловое хранилище. Через reflection подставляются зависимости и тестовые входные данные; результаты игровых транзакций не устанавливаются вручную. Серверный инвентарь заменён асинхронной заглушкой; покупки, реклама и PlayFab не вызываются. Фиксация завершения раунда проверяется до взаимодействия с наградным popup.

Перед запуском снимается SHA-256 существующих `round_recovery.json` и `saved_game.json` в реальном `Application.persistentDataPath`. После Stop/Play проверяется неизменность набора файлов и их содержимого. Координатор восстанавливает прежний `playModeStartScene`. Аудионастройки и PlayerPrefs тесты не записывают.

Для запуска требуется включённый Scene Reload. На время тестовой сессии включаются фоновые обновления через `Application.runInBackground`, затем возвращается прежнее значение; постоянные настройки проекта не меняются. Перед уничтожением fixture завершаются реальные UI fades. Ошибки Console во время тестов и teardown переводят результат в FAILED.

Протокол каждого запуска сохраняется в `.utmp/AutoRecoveryTests/<run-id>/report.md`.

Проверяются:

- начальный checkpoint до первого хода и его восстановление после настоящего Stop/Play;
- все семь комбинаций Ластика из задачи, включая успешный Миксер, завершённую и отменённую Менялку, подсказку Буковки с отменой, Замедлялку и recovery;
- ограничение одного Ластика за ход после фиксации, очистка устаревших данных отката, отсутствие повторных списаний и возвратов на восстановлении;
- успешное принятие слова игрока, завершение анимации, поле, история, очки и очередь ИИ;
- Stop/Play на очереди ИИ: ровно один настоящий ход AI, сохранение его истории, очков и следующей очереди;
- отмена временной буквы, настоящий отказ Миксера на поле с одной буквой, настоящий неудачный поиск Буковки, отказы серверного списания/возврата;
- восстановление после неудачного бустера без возвращения отменённой буквы и без повторного возврата инвентаря;
- отсутствие лишних записей при ошибке без изменения сохраняемого состояния и при повторной остановке Замедлялки;
- истечение и отмена Замедлялки, отсутствие завершённого эффекта после recovery;
- намеренный выход и фактическое завершение раунда удаляют recovery, поздний callback не создаёт его заново;
- старый recovery без `eraserRemovalCommitted`, в том числе обратимый Ластик с данными отката;
- старые ручные данные без всех необязательных полей состояния бустеров;
- повреждённый checkpoint отклоняется и удаляется только из тестового каталога.

Дополнительные постоянные сценарии autosave-3:

- реальное повторное слово `AS`: проверка поля, checkpoint и сохранности обратимого Ластика;
- настоящий `SetLetterNoSelected` → AdvicePopup → `SelectableLetter.Update` → `ModeBlinkEndEvent` → отмена и checkpoint;
- отмена только выделения, callback без временной буквы и повторный blink callback: нет лишних записей;
- `GetGameData(true)` после временной буквы и во время настоящей анимации принятия слова;
- закрытие удерживаемых реальных AdvicePopup обоих типов после смены очереди, выхода, финала и запуска нового раунда;
- отложенная доставка payload начатого реального мигания после тех же переходов, включая новую букву в той же клетке;
- поздний popup после замены буквы внутри той же очереди;
- задержанный ответ серверной заглушки до списания бустера и отложенный UI blocker перед откатом Ластика;
- настоящий длительный поиск AI, отменённый через `GameScreenBase.OnDisable`, с проверкой checkpoint;
- инъекция ошибки до применения AI и внутри реального `SetClueHighlight`: завершённая отмена сохраняется, частично изменённое поле не заменяет прежний checkpoint;
- Stop/Play с восстановлением checkpoint повторного слова, мигания, чтения данных и отменённого поиска, без replay операций инвентаря.

Обычное завершение мигания тестируется через настоящий `Update`. Для проверки защиты от устаревших событий отдельно задерживается доставка идентичного payload; производство события не подменяет нормальный сценарий, а намеренно воспроизводит позднюю доставку. Инициализация fixture выполняет обычный `GameScreenBase.Reset` до события старта, чтобы сохранённый в prefab пример текста не попадал в проверяемое слово.

## Границы проверки

- Автоматический bootstrap обычного `CoreInstaller` и его переходы между recovery, загрузочным экраном и главным меню не запускались: он использует рабочие внешние сервисы. Проверялся настоящий игровой путь восстановления через `SetGameData` → `GameScreenStartEvent` → `ResumeSavedEffects`.
- Вместо рабочего `SaveService`, привязанного к пользовательскому каталогу, использован файловый тестовый адаптер `ISaveService` с тем же `SaveGameData` и `SaveGameStorage`. Проверена независимость ручного слота в игровом жизненном цикле; выбор рабочего пути ручного сохранения не проверялся.
- Сетевые ответы PlayFab имитируются; это проверка клиентской логики, а не идемпотентности backend CloudScript. Отдельно не моделируется неоднозначный сетевой таймаут после фактически выполненного сервером возврата.
- Android force-stop и проверка на устройстве не выполнялись, согласно заданию.

## Ручная проверка обычного startup

Не запускать эти шаги с рабочими пользовательскими сохранениями.

1. Подготовить отдельную копию проекта для QA и отдельный каталог persistent data (например, отдельное имя продукта **только в копии**). Убедиться по `Application.persistentDataPath`, что путь отличается от рабочего. Использовать тестовый аккаунт PlayFab.
2. Запустить `Main` с пустым тестовым слотом. Начать раунд, дождаться первого checkpoint, затем Stop/Play: поле и начальная очередь должны восстановиться автоматически.
3. Принять слово и остановить игру на очереди ИИ. После Play должен выполниться ровно один ход ИИ; проверить поле, оба счёта, историю и очередь.
4. Применить Ластик, затем Миксер; Stop/Play. Попытка несуществующего слова не должна восстановить старую букву или вернуть Ластик. Повторить Stop/Play после одного Ластика: его обычный откат должен сохраниться.
5. Проверить штатный выход, окончание раунда и отдельное ручное сохранение. Recovery удаляется; ручной слот остаётся независимым.
6. Повредить **только тестовый** recovery JSON. При Play startup должен продолжиться в главное меню; приложение не должно зависнуть на загрузке.

## Оставшиеся ограничения

Предыдущие замечания о `WordAlreadyBeen` и `OnModeBlinkEnd` закрыты в autosave-3. Границы автоматизации остаются перечисленными выше: рабочий bootstrap/рабочий путь ручного сохранения, реальные сетевые операции и Android force-stop не выполнялись. Recovery хранит последнее завершённое состояние, а не каждый кадр UI; выделение, незавершённый путь слова, окно совета и фаза мигания не сериализуются.

Тестируется активный режим Буковки `UseCluePrototype = true`. Защита от устаревшего отложенного auto-apply добавлена и в старую отключённую ветку, но переключение на неё в этом прогоне не выполнялось. Неожиданное исключение посреди изменения поля оставляет предыдущий валидный checkpoint и по-прежнему передаётся вызывающему коду; восстановление выполняет существующая Recovery, отдельная система отката не создавалась.

В пределах проверенных операций отмены и восстановления новых незакрытых пропусков checkpoint не обнаружено. Протокол первого прогона новых тестов выявил ошибку подготовки fixture (не выполнялся обычный Reset экрана перед стартом); исправлена только тестовая инициализация, затем весь набор пройден заново. Иных подтверждённых ошибок вне согласованности Recovery, требующих изменения игрового поведения, в этом аудите не выявлено.
